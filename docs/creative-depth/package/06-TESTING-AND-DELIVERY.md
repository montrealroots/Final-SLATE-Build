# Proof That Choices Read And Bite

## Audit artifacts
Create FIELD-INVENTORY.csv and EFFECT-COVERAGE.csv as implementation proceeds. For each input/choice record: UI location, option IDs/family, persisted state, handler, engine reader, derived requirement, downstream consumer, expected observable effect, test evidence, classification and status. Classifications: mechanical decision, document/identity information, navigation, visual reference. Every mechanical decision must have a justified reader. Labels and portraits need not change quality.

Statuses: implemented+engine verified; implemented+browser verified; reference-only by design; awaiting source; awaiting external configuration; not implemented. Do not mark a feature complete merely because a button exists or its field saves. Report by category and country rather than hiding gaps in one large percentage.

## Automated contract tests
Validate schemas, stable IDs, foreign keys, duplicate suggestions, nonempty labels, compatible applicability rules, complete bindings, unit consistency, cycle-free dependencies, provider/version references and no private credentials. Fuzz option combinations within declared domains, including opposing settings, missing metadata, repeated apply/remove and changes after approval. No executable code from packs.

Each mechanical family needs a controlled comparison using the same seed and identical baseline except the chosen value. Check intermediate state and visible consequences, not just final quality. A makeup choice must alter actual demand/call sheets, not only explanatory text. A change to a character's role must preserve unrelated characters. Combine era + setting + creature + technique + production medium to expose duplicate charging.

Mutation tests for high-impact readers: remove the makeup-time consumer, territory gate, global person conflict, contract payment idempotency, immutable series profile, owner authorization, or expiry check and ensure a relevant test fails. Use targeted meaningful mutations, not exhaustive busywork.

Run journeys across desktop and existing iPhone-sized Chromium/WebKit projects, including 15 Plus and Pro Max emulation. Assert visible controls, state after save/reload, no horizontal overflow, readable touch targets, keyboard focus restoration and accessibility. Include multi-project failure paths: rejected offers, expired holds, cancellation after payment, changed design after fabrication, lost location and failed save. Fixtures clearly state what is synthetic; live imports test identity and transport separately. Physical-device checks remain a separate manual checklist.

## Balance and performance
Test at least 100 deterministic seeds for fast engine-level career scenarios where practical, with held-out seeds and a documented runtime budget; fewer full browser careers are appropriate. Do not equate passing many seeds with fun. Measure progression accessibility, insolvency rates, repeated-preset dominance, studio offer concentration, role availability, schedule deadlocks and representation of region/medium options. Thresholds are design expectations chosen before the run, not fitted after failure. Report distributions, not just averages.

Measure cold start, creation, picker search, company/person loading, location search, pack install and long-career advance on the same conditions before/after. Preserve budgets; avoid huge up-front catalogs, full-list rendering, repeated whole-world scans and storing all images in saves. A lazy route is not a performance win if its first-use stall becomes unacceptable. Keep sample devices/throttling and dataset sizes recorded.

## Exact final acceptance
1. Every inventoried field has an appropriate picker/custom-control decision and preserved existing data.
2. Every mechanical option family has an exercised consumer and a counterfactual test.
3. Every existing genre has useful definitions and suggestion routes; report counts/gaps without padding.
4. Real people can complete audition/hiring through paid work and credits, with shared availability.
5. Every playable geography entry is navigable with truthful destination coverage and labeled fallback.
6. Remaining major studio groups are imported under declared scope and usable through distinct strategy loops.
7. Optional media loads only where permitted and gracefully degrades; owner-only data has real protection.
8. Save migrations, pack refresh/removal and repeated actions conserve money and preserve history.
9. Full required CI and relevant production browser suites pass on the exact final SHA; remaining device/research issues stay explicit.

No 100% completion declaration while mechanical rows are unfinished. Do not stall unrelated feasible work on one inaccessible source. Finish all code within scope, leave precise external prerequisites, and provide a concise evidence report with commits, test commands, pass/fail/skip reasons and counts. Build scope does not authorize silently publishing private data or paid hosting.
