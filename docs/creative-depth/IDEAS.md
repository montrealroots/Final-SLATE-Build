# Choosing Ideas

Built November 11, 2026, as milestone B of the Creative Depth package. This says how the picker and its library work,
what is in the library, and how to add to it.

## What The Player Sees

Beside a field that has ideas there is a **Choose Ideas** button. The field itself is Write My Own, as it always was.
What is typed in it is never replaced unless the player applies an idea, and then only after being asked.

The picker is one dialog, the same on a phone and a desktop. On a phone it fills the screen, with its buttons above the
home indicator.

- **Recommended For This Project** lists ideas that suit the project's genres, format or way of being made, and says why.
- **Browse All** lists every idea for the field. Nothing is hidden for not suiting.
- **Saved Choices** lists ideas the player marked to come back to.
- **Build A Logline** (on the Logline field) is four lists, read as one sentence.

Opening an idea shows, before anything changes:

| Part | What it is |
| --- | --- |
| Make It Your Own | The names the idea uses, each with a suggestion the player can change |
| Who Is This For, Apply To These Scenes | For an idea about characters or scenes, which ones |
| Scenes It Offers | Scenes the idea suggests. None is added unless ticked |
| What It Sets | Every field it would write or set, in the words it would write |
| You Have Already Written | Fields with the player's words in them, each with Keep My… |
| This Changes The Shoot | For a choice an engine reads: the chair time, builds, tests, people and materials, in the engine's own figures |

Apply makes the change through the same functions the page's own controls call, so a picked value and a typed one are
the same thing afterwards. Undo Last Change takes it back like any other edit.

## Three Kinds Of Idea

| Kind | What it sets | What reads it |
| --- | --- | --- |
| Changes The Work (mechanical) | A choice an engine reads: a makeup method, a costume source, a crowd made partly in post, a shot plan, a genre, the story's year, how the project is made | The engine code its record names |
| Words You Can Edit (brief) | A premise, a conflict, what a character wants | Nothing reads them for meaning. They are the pitch and the treatment, which some people ask for by name |
| A Note (reference) | Nothing, or the look the project borrows | The Creative Brief on the Script page |

A note is said to be a note. Where an engine doesn't exist yet for something the package's starter set describes (most
camera and sound treatments), the idea is a note and says nothing in the schedule reads it yet.

## What A Save Keeps

A pick is kept as the idea's ID and version, the field it was for, when, and which characters or scenes
(`project.brief.picks`). The idea's words are never in the save. One pick of a kind stands for a target: a second makeup
method for the same character replaces the first.

## How It Is Built

| Piece | Where |
| --- | --- |
| The commands an idea can use, preview and apply | `src/engine/brief.ts` |
| The library | `src/ideas/` (`starter.ts` is generated by `tools/ideas/from-starter.py`; `more.ts` and `loglines.ts` are written by hand) |
| The picker | `src/ui/IdeaPicker.tsx`, loaded with the library the first time a picker opens |
| Makeup, costume, crowds and the story's year | `src/engine/looks.ts` (figures in `docs/ASSUMPTIONS.md`) |

An idea is a record. Its patch is a list of commands from a fixed set of sixteen, each of which sets a field the game
already has. Nothing in an idea is code, and the library is checked for anything that runs or fetches.

## Adding An Idea

1. Add a record to `src/ideas/more.ts` (or to the generator, for a starter option).
2. Give it a patch of existing commands. If it needs something the commands can't do, that is an engine change first.
3. Name what reads what it sets (`consumers`) and a test that compares outcomes with and without it (`tests`).
4. Run the contract tests, then rewrite the audit tables:

```bash
npx vitest run tests/ideas.test.ts tests/brief.test.ts
```

```bash
SLATE_WRITE_AUDIT=1 npx vitest run tests/creative-depth-audit.test.ts
```

The contract tests refuse: a repeated ID, label or sentence; an unknown command, genre, method or source; a slot with
no suggestion; a brace left in anything it writes; a reader that isn't a file; a cited test that doesn't exist.

## The Audit Tables

- `docs/creative-depth/FIELD-INVENTORY.csv`: all 247 labelled controls. 30 have ideas, 38 are creative text with none
  written yet (milestone C), 169 have no picker by design (a number, a date, a yes or no, a short list, a search, a
  name), and 10 are the picker's own.
- `docs/creative-depth/EFFECT-COVERAGE.csv`: one row per idea and one for the logline builder, with what it sets, what
  reads that, its test and its status.

Both are written from the code by `tests/creative-depth-audit.test.ts`, which fails when either is out of date.
