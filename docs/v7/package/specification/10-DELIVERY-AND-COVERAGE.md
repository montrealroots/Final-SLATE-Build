# Delivery order and evidence

## Phases
A. Inspect existing implementation and reconcile scope. Preserve the chosen phone preference and later rights-mechanics instructions. Establish baseline tests, coverage and save format. Do not repeat already completed work.
B. Introduce provenance, historical availability, stable identities and safe migrations using existing equivalents. Validate a small representative dataset end to end without treating it as final catalog coverage.
C. Scale resumable catalog/history ingestion; implement missing-data and revision policy. Keep catalog storage separate from mutable saves.
D. Complete accurate source → script → breakdown → method-specific schedule/budget → hiring → production → finish. Prioritize current extraction failures over adding inaccurate titles.
E. Connect release plans, dated charts, records, TV reports, festivals/awards and finance. Show historical playback and alternate career effects coherently.
F. Connect reputation to company decisions, film/TV first-look terms and real destination records. Validate all payments and obligations.
G. Complete worldwide scheduling, outside work and future industry evolution. Ensure finite capacity and causal decisions.
H. Complete UI/voice/accessibility and full journeys; inspect evidence; reconcile ledgers; push and merge after green CI.

Each phase can require several commits. A commit is not a claim of full feature completion. No arbitrary starter count becomes the final target. If data remains inaccessible, deliver working supported behavior and precise import/coverage gaps without falsely closing the requirement.

## Coverage report fields
Dataset/entity type; requested date window; observed date window; territories; discovered records; fetched records; validated records; published records; installed records; missing values; conflicts; sources/terms; latest import; historical/simulated boundary; next resumable checkpoint. Unknown total means unknown denominator, not 100% complete.

## Requirement statuses
Specified (this package only), not started, implemented/unverified, verified in automated tests, verified in UI, data-limited, blocked, superseded by owner. Record the reason and evidence. A partially supported feature can have verified subrequirements while its parent remains incomplete. Do not use “done” to conceal empty data or unavailable physical testing.

## Change-control examples
A player revises a scene: invalidate its breakdown and dependent bookings/finish work, preserve unaffected tasks, preview costs before applying.
An importer adds a later source observation: update future available information, retain historical versions and settled player finances.
A studio changes identity: dated company relationship, no duplicate catalog or rewritten earlier credit.
An external API becomes unavailable: cached gameplay and saves keep working; import checkpoint and clear retry behavior remain.

## Acceptance boundaries
No real-device access: report that limitation with a concise physical-device checklist; do not claim a phone is certified.
No authorized historical audience data: retain correct units and missing periods, do not substitute invented Nielsen figures.
No complete provider discovery: report the documented reachable inventory and remaining discovery gap, not “whole TMDB imported.”
No public private-contract pricing: simulate calibrated terms, retain real company identity separately.
