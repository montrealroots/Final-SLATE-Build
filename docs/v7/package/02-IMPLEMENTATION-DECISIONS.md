# Research translated into implementation

## The deliverable and the boundary
This packet adds verified source findings and structured reference records to the full v6 design. It is not the complete worldwide historical database. The source registry establishes exactly what was researched. Complete box-office access, the entire TMDB import and all award recipients have not been supplied. Do not change these gaps to complete because this packet is detailed.

## Decisions already made for Claude
1. Use ID exports for catalog discovery and detail endpoints for content. Do not use the popular-title search as the catalog denominator. Maintain separate person, work, company, network, release and credit identities. [TM01–TM12]
2. TV credits need the aggregate endpoint when displaying a whole series' people. Episode credits remain distinct; aggregate appearance counts do not establish scene-level commitments. [TM09]
3. Streaming availability is a country/date observation; it is not a studio ownership graph or a complete historical archive. [TM05]
4. Create platform-specific release route records from distribution-routes.json. In particular, subscription licensing and transactional submission are different doors. Scope policies by the date actually evidenced; current pages do not establish January terms. [REL01–REL08]
5. An observed agreement is a dated precedent, not a perpetual company affiliation. Use the three deal records to model scope variety; keep private financial terms null. [DEAL01–DEAL04]
6. Music credits substantiate people/work links. They do not establish license cost, personal availability, rights ownership or permission to include recordings. [AW11; MUS01–MUS04]
7. Adaptation needs a structured multi-viewpoint model. The supplied Elantris correction overrides the faulty sole-lead assumption, but does not pretend to supply an exhaustive cast or ending. [BOOK01–BOOK03]
8. Production tasks carry asset/version dependencies. The supplied seven pipeline scaffolds are original design informed by role research; actual durations and budgets are simulated. [PROD01–PROD04]
9. Camera capability constrains compatible tasks; it does not directly increase writing, acting or reception. Recording mode—not model name alone—determines capture feasibility. [CAM01–CAM03]
10. Every official rule extract here is marked incomplete. It can conclusively fail a known violated condition; it cannot conclusively approve an entry without the remaining rules. [AW03–AW06; FEST02–FEST03]

## Full causal example: source to opportunity
Player chooses source → preview separates canonical facts and proposed creative treatment → format/method generates required tasks → cast/crew/kit reservations create commitments → changes invalidate only dependent work → approved delivery creates destination eligibility → release reports generate receivables → settlement repays backers → available surplus can be withdrawn → completed role-specific evidence changes reputation → studio capacity/fit/reputation produce a negotiable offer.

Each arrow is a persistent relation with a test. No hidden automatic purchase. A declined offer returns to a usable state. A repaired production does not erase already spent cash. A failed release does not remove the project from the filmography.

## History and event policy
Maintain actual event date, evidence publication date, retrieval date and simulation availability separately. Dates known only to a day should not manufacture an exact ceremony result time. Unknown original publication stays null. Calendar events can occur on a known date without proving how early they were announced.

Strict historical playback suppresses uncertain-availability observations until verified; an optional modeled playback can use a documented inferred publication rule. The included Netflix week uses inferred Tuesday availability and must retain that label. Current corrected data is not necessarily what audiences knew at the original time. Preserve versioned snapshots and late corrections.

Historical box-office facts remain separate from player-world outcomes. Offer Historical Records and Your Timeline views. Player competition changes simulated bookings/reach and opportunities; it does not silently rewrite sourced grosses. Awards that include player entries can diverge within Your Timeline while Historical Records remains intact.

## Monetary model
Follow contract-defined bases, not universal distributor percentages. Distinguish gross ticket sales, rental/owner receipts, guaranteed advances, recoupable costs, settlement and distributable profit. A current published platform share must not become a universal platform rate. Fees without evidence remain calibrated variables; use a proposed offer with clear assumptions.

Reputation model parameters are original game design. Evidence dimensions are separate, contributions bounded, duplicate events ignored, grades require multiple completed works. Keep skill/attributes as a separate future interface. A high reputation can raise access or negotiation leverage while the studio still declines for capacity, format or project economics.

## Box-office import decision
BOX01 rules out redistributing a scraped complete The Numbers dataset in this packet. Build a neutral import format accepting a licensed export or independently authorized observations. Do not replace missing weeks with annual-total interpolation. Until an adequate feed exists, historical charts must display coverage limits; simulated player charts can still operate. This is an access limitation, not a reason to leave the engine disconnected.

## UI decision
Preserve the owner’s chosen desktop-like visual arrangement and provide readable phone operation. Measure touch controls, dialogs and zoom. A scaled desktop mode may coexist with a reflow option; neither should hide features. Source citations go to Settings → Credits where allowed. Keep historically uncertain or simulated values legible at the point where they influence a decision.
